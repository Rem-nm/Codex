# 配置事务和恢复

所有会改变运行 inbound 的节点、状态、限额和限速操作都调用同一个状态事务入口：

1. 对现有 `manager.json`、节点、流量、历史、接口和 tc 计划执行结构、类型、取值、唯一性与交叉引用校验。
2. 在 `/run/ss-manager/` 生成候选节点、流量、历史和 sing-box 配置，执行 `sing-box check`。
3. 创建常规备份，并在 `/etc/ss-manager/state-transaction/` 保存事务前节点、流量、历史、配置、服务运行状态和阶段日志。
4. 对每个快照和目录执行 `fsync`，再写入 `switching_config`、`applying_tc`、`committing_state` 等持久阶段。
5. 切换配置；操作前服务正在运行时快速 restart，用户已停止服务时保持停止。
6. 检查服务状态、唯一 sing-box PID、完整配置以及每个启用节点和预期地址族的监听 PID 所有权；SS2022 检查 TCP/UDP，VLESS 检查 TCP，Hysteria2/TUIC 检查 UDP。新节点和全部原有节点都必须仍然存在。
7. 应用并检查带 action cookie、index 和精确 filter handle 所有权的 tc 规则，重置候选内核计数基线。
8. 依次原子提交节点、流量和历史文件，再做最终运行健康检查。
9. 持久写入 `committed` 才是提交点；之后日志或旧备份清理失败只会延后清理，不会错误回滚已生效状态。

普通失败立即从持久快照恢复。SIGKILL、进程崩溃或断电后，下次 `rem`/定时维护会先检查日志：未提交阶段恢复事务前状态；`committed` 阶段只清理残留日志。恢复自身再次中断时，日志仍保留并可重复执行。

协议专属字段也只能通过这一入口变更。VLESS 的 UUID、Reality KeyPair 和 Short ID 重新生成前先确认客户端失效风险；Hysteria2 的密码、TUIC 的 UUID/Password 或两者的 TLS 证书重新生成都会使现有客户端信息失效，提交前必须验证证书 SAN、私钥匹配和 pin。候选配置检查与运行健康检查成功后才提交统一节点数据库。Reality Private Key、HY2/TUIC TLS 私钥只经权限为 600 的候选文件传递，不进入终端普通输出或外部命令参数。

交互操作以非零状态结束时，父菜单会在返回前检查两类持久日志并立即执行同样的恢复；恢复失败就停止菜单，避免下一项操作落在半完成状态。若恢复切换了 manager 版本，父菜单会立即 `exec` 对应版本入口。

## 安装、系统设置和 manager 更新

`install.sh`、BBR/TFO 与默认路由接口系统设置、sing-box/manager 自更新使用更宽的 `/etc/ss-manager/install-transaction/`。它会保存程序目录、全部状态文件、tc 计划、sing-box 二进制与配置、`rem`、项目 sysctl 文件、服务定义/启用状态、每个服务的运行状态、程序切换暂存路径以及实时 BBR/TFO 值。事务前快照中的嵌套文件和目录都会同步到磁盘后才开始修改；写入 `committed` 前还会再次同步全部当前目标、删除所在父目录和服务启用目录，确保提交标记不会先于它声明的数据落盘。回滚会先依据当前持久 tc 计划清理当前规则，再恢复并重建旧计划，最后恢复各服务原有运行状态。

安装范围内的 TFO 配置更新可能短暂建立内层状态事务。外层安装事务是权威恢复边界：外层回滚完成程序、状态、服务和 tc 恢复后才清除该内层日志；反过来，存在未恢复状态事务时拒绝建立新的安装事务。

安装依赖由系统包管理器在事务建立前补齐，已安装的软件包不会在失败时卸载；项目自身的程序、数据、服务、HY2/TUIC 证书和内核设置会完整回滚。重复安装检测到现有 VLESS 节点时，还会在提交前用已选择的 sing-box 和本机安全随机源实际验证 UUID、Reality KeyPair 与 Short ID 的生成/校验能力；存在 TUIC 节点时验证 UUID/Password 生成能力，存在 HY2/TUIC 节点时验证证书、私钥、SAN 和 pin。manager 更新在切换前验证官方 Release SHA256、版本、归档结构、无链接归档、全部 shell 语法及新入口自检能力；新程序还会在不迁移、不提交状态的只读预检中把现有 schema 1/2/3/4 节点生成完整候选配置，并用当前受管 sing-box 检查。该预检除权限为 700 的 `/run/ss-manager/` 候选文件外不创建或修改永久目录；旧版 traffic 状态仍需迁移时则拒绝 manager-only 更新并保留给完整安装事务处理。现有 VLESS/TUIC 节点存在时，预检还会验证对应凭据生成能力，存在 HY2/TUIC 时验证证书状态。若断电恰好发生在目录重命名间隙，增强后的 `rem` 只会从唯一、root 所有的旧程序目录启动持久恢复；恢复完成后按日志清理准确的暂存目录，发现多个候选时拒绝猜测。

旧 schema 1/2/3 节点迁移发生在任何菜单编辑之前。安装/修复路径由外层安装事务保护；迁移本身还会先创建语义完整的常规快照，并以原子文件替换把旧 SS2022 节点增加 `protocol: "shadowsocks"`（schema 1）或只提升顶层版本（schema 2/3），最终写入 schema 4。候选验证或持久提交失败时恢复迁移前节点文件，避免留下半升级状态。

## 备份

常规配置变更默认保留最近 10 个备份，也可从菜单立即创建手动快照。快照先写入同一文件系统的隐藏准备目录，完成状态语义检查和全树 `fsync` 后才通过目录重命名发布。列出、恢复和自动清理只接受目录名、元数据、必要文件与节点/流量/历史语义都完整的 Ss2022 快照；不完整目录或管理员放在 `backups/` 下的其他内容会保留。schema 4 快照完整保存 VLESS UUID、Reality Private/Public Key、Short ID、SNI、握手目标和 Flow，HY2 密码，以及 TUIC UUID/Password/固定参数，并保存 HY2/TUIC TLS SNI、证书 pin 和证书目录；恢复时不重新生成，因此原客户端身份继续可用。删除节点时是否保留流量历史由用户确认；保留时把当前快照写入 `traffic-history.json` 的 `deleted_nodes`，选择不保留则同时清除该 Node ID 的已结算周期，并删除其派生证书目录。
